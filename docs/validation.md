# 实测记录和复现范围

记录日期：2026-10-21。环境为 README 中列出的 Orin NX 16GB、达妙 V2、Pi5-IMX219-77、CSI0、L4T R39.2.1。

## 从不可见到出图

之前没有 IMX219 DT 节点、没有 sensor probe、没有 `/dev/video0`。启用设备树并重启后，`imx219 9-0010` 绑定，`/dev/video0` 出现，media graph 包含 sensor、NVCSI、VI。

验证结果：

- V4L2：1920×1080 RAW，连续 60 帧，命令返回 0，输出约 30.02 fps。
- Argus→OpenCV：1920×1080@30 输入、960×540 BGR 输出，90 帧、随后 300 帧连续采集均完成。
- Argus：1280×720@60 配置下完成 120 帧并收到 EOS；该结果没有单独测量传感器到应用的端到端延迟。
- 五种驱动模式均完成原尺寸 JPEG 拍摄。JPEG 是应用保存结果，不代表使用了 NVENC。

## 720p30 时序

`examples/check_720p30.py` 对应的原始短时实验，先预热 60 帧，再测量 150 帧：

| 指标 | 结果 |
|---|---:|
| 输出 | 1280×720×3 BGR |
| 接收平均帧率 | 30.012 fps |
| 帧到达间隔中位数 | 33.318 ms |
| 帧到达间隔 P95 | 36.382 ms |
| 最大帧到达间隔 | 43.931 ms |

这是采集和 BGR 转换的结果。没有包含二维码算法、网络、串口、显示、录像或完整曝光到结果延迟，不能宣称“算法稳定 30fps”或“严格每 33.3ms 到一帧”。

## 第二次白纸参考修正

固定 `wbmode=2`，曝光补偿 -0.7 EV，输出 960×540。LUT 根据白纸中央区域计算，再另行采集 180 帧验证。

| 区域 | 修正前 RGB 中位值 | 修正后 RGB 中位值 |
|---|---|---|
| 拟合区域 | 159 / 185 / 214 | 198 / 195 / 192 |
| 左侧独立区域 | 150 / 179 / 209 | 187 / 189 / 188 |
| 右侧独立区域 | 167 / 192 / 219 | 207 / 201 / 196 |

修正后的独立区域 `(max(R,G,B)-min(R,G,B))/mean(R,G,B)` 约为 1.1% 和 5.5%。这个指标只是白点通道差异，不是 ΔE，也不是完整颜色准确度。

本次 960×540 LUT 平均开销约 1.004 ms/帧。采样、曝光和不同图像区域存在差异；不能把这些增益当成通用配置。

```text
2b9325fac4fe5654e87dbd90c9ccb9824ec3660888e1ed19b91ce8ffc20bd446
```

当前公开版本仅合并相机 overlay。此前完成重启和出图的设备树同时包含其他载板改动，因此不能用其整个 DTB 的校验和作为本仓库相机单独构建的验收标准。

相机单独构建通过离线拓扑检查、重复节点与 phandle 检查，以及已有无关属性保持不变检查；尚未单独重启验收。公开整理过程未修改本机启动配置。

## 公开脚本检查

整理后的预览示例分别以默认自动曝光、固定 20 ms / 1.5x / ISP 1x、自动曝光上限 5 ms / 增益上限 4x / ISP 1x 完成各 90 帧无保存采集，命令均返回 0。仅验证能设置参数并持续出图，没有读取逐帧实际曝光元数据。6 项启动配置与回退保护测试全部通过，Python 文件通过语法编译检查；相机单独设备树构建通过离线检查。

## 仍然存在的限制

- 当前仍观察到图像噪点、不同区域的光照/色差；没有完整色卡、空间均匀性和室外验证。
- 未做长时间温度、振动、快速运动、掉帧恢复和飞行测试。
- 未验收 CSI1、双摄、不同模组、不同载板或不同软件版本。
- 整理后的安装器默认预览已验证，启动配置变换和回退保护通过离线测试；新的安装/回退代码没有再次在真实 `/boot` 上执行写入。
- 不公开本机照片、完整设备树导出、启动参数、UUID、MAC、用户路径或第三方二进制文件。
